## 編解碼的兩條路徑

`encoding/json` 的核心是**反射 + 型別快取**。

### 編碼

```text
json.Marshal(v):
    ① 取得 v 的 reflect.Type
    ② 查快取：這個型別的「編碼器函式」建好了嗎？
       沒有 → 走訪所有欄位、解析 tag、產生一個編碼器閉包、存進快取
    ③ 執行編碼器，把結果寫進一個從 sync.Pool 取來的 buffer
    ④ 複製一份回傳（因為 buffer 要還給 pool）
```

**型別分析只做一次**。第一次編碼某個型別比較慢，之後就快得多。這是所有反射型函式庫的標準做法（見 [反射](reflect.html#怎麼降低成本)）。

### 解碼

```text
json.Unmarshal(data, &v):
    ① 掃描 JSON 語法，驗證格式
    ② 依 v 的型別逐欄位填入
    ③ 欄位名稱比對：先試精確比對，再試「忽略大小寫」比對
```

!!! warning "欄位比對會忽略大小寫"
    ```go
    type User struct {
        Name string `json:"name"`
    }

    // 這三個都會填進 Name
    json.Unmarshal([]byte(`{"name":"a"}`), &u)
    json.Unmarshal([]byte(`{"Name":"b"}`), &u)
    json.Unmarshal([]byte(`{"NAME":"c"}`), &u)
    ```

    這是 v1 的既定行為，為了相容性不能改。如果你需要嚴格比對，只能自己寫 `UnmarshalJSON`，或改用 v2（見文末）。

## struct tag 完整語意

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Product struct {
	ID       int      `json:"id"`                 // 改名
	Name     string   `json:"name"`               //
	Desc     string   `json:"desc,omitempty"`     // 零值時省略
	Price    float64  `json:"price,string"`       // 編碼成字串
	Internal string   `json:"-"`                  // 完全忽略
	Dash     string   `json:"-,"`                 // 欄位名真的叫 "-"
	Tags     []string `json:"tags,omitempty"`     //
	Meta     any      `json:"meta,omitempty"`     //
	Legacy   string   //  沒有 tag → 用欄位名 "Legacy"
	hidden   string   //  未匯出 → 永遠被忽略
}

func main() {
	p := Product{
		ID:       1,
		Name:     "咖啡豆",
		Price:    450.5,
		Internal: "不會出現",
		Dash:     "破折號欄位",
		hidden:   "看不到",
	}

	b, _ := json.MarshalIndent(p, "", "  ")
	fmt.Println(string(b))
}
```

```text
{
  "id": 1,
  "name": "咖啡豆",
  "price": "450.5",
  "-": "破折號欄位",
  "Legacy": ""
}
```

| tag | 效果 |
| --- | --- |
| `json:"name"` | 使用 `name` 當 JSON 鍵 |
| `json:"name,omitempty"` | 值為零值時整個欄位省略 |
| `json:"name,string"` | 數字／布林編碼成 JSON 字串 |
| `json:"-"` | 完全忽略此欄位 |
| `json:"-,"` | 鍵名就是 `"-"`（注意結尾的逗號） |
| `json:",omitempty"` | 保留欄位名，但套用 omitempty |

### `omitempty` 的陷阱

**`omitempty` 判斷的是 Go 的「零值」，不是「語意上的空」。**

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Settings struct {
	Enabled bool    `json:"enabled,omitempty"`
	Count   int     `json:"count,omitempty"`
	Ratio   float64 `json:"ratio,omitempty"`
	Name    string  `json:"name,omitempty"`
	Items   []int   `json:"items,omitempty"`
	Nested  struct{ X int } `json:"nested,omitempty"` // ✗ struct 沒有 omitempty 效果
}

func main() {
	b, _ := json.Marshal(Settings{})
	fmt.Println(string(b))
}
```

```text
{"nested":{"X":0}}
```

`false`、`0`、`""`、`nil` slice 全部被省略——**即使你是刻意要傳 `false`**。而空 struct 反而不會被省略（`omitempty` 對 struct 無效）。

**解法：用指標區分「未設定」與「設定為零值」。**

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Settings struct {
	Enabled *bool `json:"enabled,omitempty"`
	Count   *int  `json:"count,omitempty"`
}

func main() {
	f := false
	n := 0

	// 明確設定為 false / 0
	b, _ := json.Marshal(Settings{Enabled: &f, Count: &n})
	fmt.Println(string(b)) // {"enabled":false,"count":0}

	// 未設定
	b2, _ := json.Marshal(Settings{})
	fmt.Println(string(b2)) // {}
}
```

!!! version "Go 1.24：`omitzero`"
    Go 1.24 加入 `omitzero`，語意更清楚：**只在值等於該型別的零值時省略**，而且對 struct 有效、對 `time.Time` 這種有 `IsZero()` 方法的型別會呼叫它。

    ```go
    type Event struct {
        Name string    `json:"name"`
        At   time.Time `json:"at,omitzero"`   // 零時間會被省略
        Meta Metadata  `json:"meta,omitzero"` // 零值 struct 會被省略
    }
    ```

    `omitempty` 對 `time.Time` 完全無效（`time.Time` 是 struct，永遠不是「empty」），所以以前必須用 `*time.Time`。`omitzero` 解決了這個長年的痛點。

## 型別對應

### 預設對應

| JSON | Go（解碼到 `any` 時） |
| --- | --- |
| `null` | `nil` |
| `true` / `false` | `bool` |
| 數字 | **`float64`** |
| 字串 | `string` |
| 陣列 | `[]any` |
| 物件 | `map[string]any` |

!!! danger "數字一律變成 float64"
    ```go
    var v any
    json.Unmarshal([]byte(`{"id": 9007199254740993}`), &v)
    m := v.(map[string]any)
    fmt.Printf("%.0f\n", m["id"]) // 9007199254740992 ← 精度掉了！
    ```

    `float64` 只能精確表示 2⁵³ 以內的整數。超過的大整數（例如雪花演算法產生的 ID、某些資料庫的 bigint）會被靜默截斷。

    **解法一：解碼到具體型別。**

    ```go
    type Resp struct{ ID int64 `json:"id"` }
    ```

    **解法二：用 `Decoder.UseNumber()`。**

    ```go
    package main

    import (
        "encoding/json"
        "fmt"
        "strings"
    )

    func main() {
        dec := json.NewDecoder(strings.NewReader(`{"id": 9007199254740993}`))
        dec.UseNumber()

        var v map[string]any
        dec.Decode(&v)

        n := v["id"].(json.Number)
        i, _ := n.Int64()
        fmt.Println(i) // 9007199254740993 ← 精確
    }
    ```

## 自訂編解碼

實作 `json.Marshaler` 與 `json.Unmarshaler` 介面：

```go
package main

import (
	"encoding/json"
	"fmt"
	"strings"
)

type Status int

const (
	StatusPending Status = iota
	StatusActive
	StatusClosed
)

var statusNames = map[Status]string{
	StatusPending: "pending",
	StatusActive:  "active",
	StatusClosed:  "closed",
}

func (s Status) MarshalJSON() ([]byte, error) {
	name, ok := statusNames[s]
	if !ok {
		return nil, fmt.Errorf("未知狀態: %d", int(s))
	}
	return json.Marshal(name)
}

func (s *Status) UnmarshalJSON(data []byte) error {
	var name string
	if err := json.Unmarshal(data, &name); err != nil {
		return err
	}
	for k, v := range statusNames {
		if strings.EqualFold(v, name) {
			*s = k
			return nil
		}
	}
	return fmt.Errorf("未知狀態: %q", name)
}

type Task struct {
	Title  string `json:"title"`
	Status Status `json:"status"`
}

func main() {
	b, _ := json.Marshal(Task{Title: "寫文件", Status: StatusActive})
	fmt.Println(string(b)) // {"title":"寫文件","status":"active"}

	var t Task
	json.Unmarshal([]byte(`{"title":"審核","status":"closed"}`), &t)
	fmt.Printf("%+v\n", t) // {Title:審核 Status:2}
}
```

!!! warning "`MarshalJSON` 用值接收者、`UnmarshalJSON` 用指標接收者"
    這不對稱是必要的：

    - `MarshalJSON` 用**值**接收者，這樣 `Status` 與 `*Status` 都能編碼（見[方法集規則](typecheck.html#介面滿足結構化型別)）。
    - `UnmarshalJSON` 必須用**指標**接收者，因為它要修改接收者。

    如果 `MarshalJSON` 用了指標接收者，把 `Status` 值放進 struct 欄位時就不會被呼叫——這是很難察覺的 bug。

### 避免無窮遞迴

在自訂方法裡直接 `json.Marshal(自己)` 會無窮遞迴。用型別別名切斷：

```go
package main

import (
	"encoding/json"
	"fmt"
	"time"
)

type Event struct {
	Name string    `json:"name"`
	At   time.Time `json:"at"`
}

func (e Event) MarshalJSON() ([]byte, error) {
	type alias Event // ✓ alias 沒有 MarshalJSON 方法，不會遞迴

	return json.Marshal(struct {
		alias
		AtUnix int64 `json:"at_unix"` // 加一個衍生欄位
	}{
		alias:  alias(e),
		AtUnix: e.At.Unix(),
	})
}

func main() {
	b, _ := json.Marshal(Event{Name: "deploy", At: time.Unix(1700000000, 0).UTC()})
	fmt.Println(string(b))
}
```

```text
{"name":"deploy","at":"2023-11-14T22:13:20Z","at_unix":1700000000}
```

`type alias Event` 建立一個新的具名型別，它繼承欄位但**不繼承方法**——這正是我們要的。

## 串流處理

`Marshal`／`Unmarshal` 會把整份資料放在記憶體裡。處理大檔案或網路串流時用 `Encoder`／`Decoder`。

```go
package main

import (
	"encoding/json"
	"fmt"
	"io"
	"strings"
)

type Record struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
}

func main() {
	// JSON Lines：每行一個物件
	input := `{"id":1,"name":"a"}
{"id":2,"name":"b"}
{"id":3,"name":"c"}`

	dec := json.NewDecoder(strings.NewReader(input))
	for {
		var r Record
		if err := dec.Decode(&r); err == io.EOF {
			break
		} else if err != nil {
			fmt.Println("錯誤:", err)
			break
		}
		fmt.Printf("%+v\n", r)
	}
}
```

### 逐項處理大型陣列

```go
package main

import (
	"encoding/json"
	"fmt"
	"strings"
)

func main() {
	input := `[{"id":1},{"id":2},{"id":3}]`
	dec := json.NewDecoder(strings.NewReader(input))

	// 讀掉開頭的 '['
	if _, err := dec.Token(); err != nil {
		panic(err)
	}

	for dec.More() {
		var item struct{ ID int }
		if err := dec.Decode(&item); err != nil {
			panic(err)
		}
		fmt.Println("處理", item.ID)
	}

	// 讀掉結尾的 ']'
	dec.Token()
}
```

即使陣列有一百萬個元素，記憶體用量也只跟單一元素的大小相關。

### 嚴格模式

```go
dec := json.NewDecoder(r)
dec.DisallowUnknownFields() // 遇到未知欄位就報錯
```

處理設定檔時很有用——使用者打錯欄位名時會得到明確的錯誤，而不是被靜默忽略。

## 效能

### 基準對照

```go
package main

import (
	"encoding/json"
	"fmt"
	"testing"
)

type Item struct {
	ID    int     `json:"id"`
	Name  string  `json:"name"`
	Price float64 `json:"price"`
	Tags  []string `json:"tags"`
}

func main() {
	items := make([]Item, 1000)
	for i := range items {
		items[i] = Item{i, "item", 9.99, []string{"a", "b"}}
	}
	data, _ := json.Marshal(items)

	r1 := testing.Benchmark(func(b *testing.B) {
		b.ReportAllocs()
		for i := 0; i < b.N; i++ {
			_, _ = json.Marshal(items)
		}
	})
	r2 := testing.Benchmark(func(b *testing.B) {
		b.ReportAllocs()
		for i := 0; i < b.N; i++ {
			var out []Item
			_ = json.Unmarshal(data, &out)
		}
	})

	fmt.Println("Marshal:  ", r1, r1.MemString())
	fmt.Println("Unmarshal:", r2, r2.MemString())
}
```

### 優化技巧

| 技巧 | 效果 |
| --- | --- |
| 用具體 struct 而非 `map[string]any` | 快 2–5 倍，配置大幅減少 |
| 用 `Encoder` 直接寫進 `io.Writer` | 省掉中間的 `[]byte` |
| `sync.Pool` 重用 buffer | 減少 GC 壓力 |
| 欄位少一點、巢狀淺一點 | 反射走訪成本降低 |
| 程式碼生成（`easyjson` 等） | 快 3–10 倍，但增加建置複雜度 |

```go
// ✗ 多一次完整的複製
b, _ := json.Marshal(v)
w.Write(b)

// ✓ 直接寫出
json.NewEncoder(w).Encode(v)
```

!!! tip "HTTP handler 的正確寫法"
    ```go
    func handler(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "application/json")

        if err := json.NewEncoder(w).Encode(resp); err != nil {
            // 注意：此時 header 已經送出，無法再改 status code
            slog.Error("encode failed", "err", err)
        }
    }
    ```

    `Encode` 會自動在結尾加上換行符號，這是它跟 `Marshal` 的一個小差異。

## json/v2

!!! version "Go 1.25 實驗性引入，Go 1.26 仍需 GOEXPERIMENT"
    v1 的 `encoding/json` 有一些無法在相容性承諾下修正的設計問題。Go 團隊在 Go 1.25 引入了實驗性的 `encoding/json/v2` 與底層的 `encoding/json/jsontext`。

    **Go 1.26 的狀態**：仍然需要明確啟用：

    ```bash
    GOEXPERIMENT=jsonv2 go build ./...
    ```

    啟用後，`encoding/json`（v1）會改由 v2 實作，但保持 v1 的行為語意；同時 `encoding/json/v2` 可以直接 import。

    **預計 Go 1.27 成為預設**，屆時改用 `GOEXPERIMENT=nojsonv2` 才能切回舊實作。

    因為它還在演進中，**正式環境暫時不建議使用**。以下只列出設計方向。

v2 想解決的幾個 v1 問題：

| v1 的問題 | v2 的作法 |
| --- | --- |
| 欄位比對忽略大小寫（無法關閉） | 預設精確比對，可選擇忽略大小寫 |
| 錯誤訊息不夠明確（不知道錯在哪個欄位） | 錯誤帶有 JSON 指標路徑 |
| 沒有真正的串流 API | `jsontext` 提供低階的 token 串流 |
| `omitempty` 語意混亂 | 選項系統更清晰 |
| 選項只能透過 struct tag | 支援呼叫時傳入選項 |
| `nil` slice 編碼成 `null` | 可設定成 `[]` |
| 重複的 JSON 鍵被靜默接受 | 預設拒絕 |
| 效能（尤其是解碼） | 顯著改善 |

```go
// v2 的選項式 API 概念（實驗中，API 可能改變）
import (
    "encoding/json/v2"
    "encoding/json/jsontext"
)

data, err := json.Marshal(v,
    jsontext.WithIndent("  "),
    json.FormatNilSliceAsEmpty(true),
)
```

**現階段的建議**：知道它的存在，追蹤它的進展，但正式專案繼續用 v1。等它成為預設（Go 1.27）而且生態成熟後再遷移。

## 常見錯誤總覽

| 症狀 | 原因 |
| --- | --- |
| 欄位沒有被編碼 | 欄位未匯出（小寫開頭） |
| 解碼後欄位是零值 | 傳的不是指標，或欄位未匯出 |
| `json: unsupported type: chan int` | channel、func、complex 無法編碼 |
| `json: unsupported value: +Inf` | `NaN`、`Inf` 無法表示成 JSON |
| 大整數精度遺失 | 解碼到 `any` 變成 `float64`，用 `UseNumber()` |
| 時間格式不對 | `time.Time` 預設用 RFC 3339，要別的格式得自訂 |
| `omitempty` 對 `time.Time` 沒用 | 用 `omitzero`（1.24+）或 `*time.Time` |
| 無窮遞迴 / 堆疊溢位 | 自訂 `MarshalJSON` 裡呼叫了 `json.Marshal(自己)` |
| 循環參照造成 stack overflow | JSON 沒有參照概念，要自己切斷循環 |
